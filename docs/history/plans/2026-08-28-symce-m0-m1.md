# SymCE M0+M1 Implementation Plan


**Goal:** Prove the TI-84 Plus CE homescreen hook can intercept and swallow `[ENTER]` on OS 5.8.4, and get the forked CAS engine building and testing on both macOS and eZ80 — producing the size measurement that selects the stub→engine strategy.

**Architecture:** Two spikes. M0 installs a prebuilt hook logger in CEmu and reads the real register values the OS passes to a homescreen hook, replacing extrapolated TI-83 Plus documentation with measured fact. M1 forks PineappleCAS, strips its GUI, and stands up a dual-target build so the CAS engine can be developed natively on macOS instead of over a USB cable.

**Tech Stack:** CE C/C++ toolchain v15.0 (`ez80-clang`, LLVM), CEmu v2.0 (eZ80 debugger), Cap'n Hook (MIT), PineappleCAS (MIT), clang on macOS arm64, GNU make.

## Global Constraints

- Target hardware: TI-84 Plus CE, OS **5.8.4.0058**, jailbroken with arTIfiCE v2.1 + AsmHook.
- Host: macOS 27.0, **arm64**. Use `-arm` / `_arm` release assets only.
- All vendored third-party source is **MIT**; preserve upstream `LICENSE` files verbatim.
- Vendored upstream code lives under `vendor/` and is **not** modified in place — SymCE changes go in `src/`.
- `cmake` and `wget` are **not installed**; use `curl` and plain `make`.
- `gh` is **not authenticated**; use `curl` against the public GitHub API, never `gh api`.
- Never commit ROM images or `.8xp`/`.8xv` binaries (already in `.gitignore`).
- Hook bodies must begin with byte `$83` and be position-independent (spec §4.6).

- [ ] **Step 3: Run it**

Expected in the console: a line per hook type from `hook_Install`, e.g. `Err 0` repeated. `Err 0` is `HOOK_SUCCESS`. Any nonzero value maps to the `hook_error_t` enum in `vendor/capnhook/src/capnhook.h` — resolve it before continuing.

- [ ] **Step 4: Trigger the homescreen hook and capture registers**

Return to the home screen (`2nd` `MODE`). Type `2` `X,T,θ,n` `+` `2` `X,T,θ,n`, then press `ENTER`.

The console fills with lines shaped like:

```
  HOMESCREEN: af:0100 bc:000000 de:000000 hl:000000 ix:D1A880 iy:D00080
```

The **high byte of `af`** is register `A` — the event code. The **high byte of `bc`** is register `B` — the keycode on event 1.

Copy every `HOMESCREEN:` line from the moment you pressed `ENTER`.

- [ ] **Step 5: Repeat for the numeric baseline**

Clear the screen. Type `2` `+` `2`, press `ENTER`. Capture the `HOMESCREEN:` lines again.

Comparing symbolic and numeric entries shows whether the hook sees any difference before parsing — it should not, which is exactly why SymCE must inspect the edit buffer itself rather than relying on the OS to classify.

## Task 5: Prove the hook can swallow ENTER

The single go/no-go gate for the whole project. If `[ENTER]` cannot be swallowed, the hook-based architecture is dead and the answer is a full-takeover shell.

**Files:**
- Create: `spikes/swallow/makefile`, `spikes/swallow/src/hook.asm`, `spikes/swallow/src/main.c`

**Interfaces:**
- Consumes: measured event code and keycode from Task 4.
- Produces: a yes/no answer on the core architectural assumption.

- [ ] **Step 1: Write the spike hook**

Substitute the measured values from Task 4 for `EVENT_KEYPRESS` and `KEY_ENTER`. Create `spikes/swallow/src/hook.asm`:

```asm
include '../../../vendor/capnhook/src/capnhook.inc'

EVENT_KEYPRESS := 1     ; <- replace with the value measured in Task 4
KEY_ENTER      := 5     ; <- replace with the value measured in Task 4

public _hook
_hook:
	db	$83                       ; hook magic
	push	iy,ix,hl,de,bc,af
	cp	a,EVENT_KEYPRESS          ; A = event code
	jq	nz,.pass_through
	ld	a,b                       ; B = keycode
	cp	a,KEY_ENTER
	jq	nz,.pass_through
	res	0,(iy-flag_continue)      ; we are returning a value to the OS
	pop	af,bc,de,hl,ix,iy
	or	a,a                       ; reset Z -> NZ -> swallow the key
	ret
.pass_through:
	set	0,(iy-flag_continue)      ; let other hooks run
	pop	af,bc,de,hl,ix,iy
	cp	a,a                       ; set Z -> OS handles normally
	ret
hook_size = $ - _hook

public _hook_size
_hook_size:
	dl	hook_size
```

- [ ] **Step 2: Write the installer**

Create `spikes/swallow/src/main.c`:

```c
#include <capnhook.h>
#include <debug.h>

extern hook_t hook;
extern size_t hook_size;

int main(void) {
    hook_error_t err = hook_Install(0x53594D, &hook, hook_size,
                                    HOOK_TYPE_HOMESCREEN, 5,
                                    "SymCE ENTER swallow spike");
    dbg_sprintf(dbgout, "install err %u\n", err);
    err = hook_Sync();
    dbg_sprintf(dbgout, "sync err %u\n", err);
    return 0;
}
```

`0x53594D` is ASCII `SYM`, a placeholder ID for the spike only. Spec §14 requires registering a real ID before release.

- [ ] **Step 3: Write the makefile**

Create `spikes/swallow/makefile`:

```makefile
NAME        = SWALLOW
COMPRESSED  = NO
DESCRIPTION = "SymCE ENTER swallow spike"

EXTRA_CFLAGS = -I../../vendor/capnhook/src
EXTRA_LDFLAGS = -L../../vendor/capnhook/src

include $(shell cedev-config --makefile)
```

- [ ] **Step 4: Build**

```bash
cd <repo>/spikes/swallow && make
ls -la bin/
```

Expected: `bin/SWALLOW.8xp`. Assembler errors here are almost always the PIC constraint — any absolute reference to a label inside the hook must go through `ix`.

- [ ] **Step 5: Run it and test the gate**

Send `bin/SWALLOW.8xp` to CEmu and run it. Console should print `install err 0` and `sync err 0`.

Return to the home screen. Type `2` `+` `2` and press `ENTER`.

Expected: **nothing happens.** No `4`, no error, no new history line. The OS never parsed the entry.

This is the whole M0 result. If ENTER is swallowed, the architecture holds and every later milestone is viable. If the OS evaluates anyway, the homescreen hook cannot preempt parsing on 5.8.4 and the project pivots to a full-takeover shell.

- [ ] **Step 6: Verify clean uninstall (safety invariant §9.5)**

Send and run the logger from Task 3 again, then in CEmu do **Calculator → Reset**. Confirm the calculator returns to normal: `2+2` gives `4`.

A spike that cannot be removed is a spike that bricks the real calculator. Do not proceed to hardware until this passes.

Append to `docs/history/notes/m0-hook-recon.md`:

```markdown
- Calculator recovered after reset: YES / NO

```

## Task 7: Host build

Upstream's root makefile is CE-only (`include $(shell cedev-config --makefile)`), so the host build must be authored.

**Files:**
- Create: `src/symcore/makefile.pc`

**Interfaces:**
- Consumes: fork from Task 6, macro name from Task 6 Step 3.
- Produces: `build/symcore-pc` executable; `make -f makefile.pc test` target.

- [ ] **Step 1: Write the host makefile**

Create `src/symcore/makefile.pc`:

```makefile
# symcore host build (macOS arm64 / Linux).
# Upstream's root makefile targets eZ80 only; this is the host counterpart.
# __TICE__ is deliberately left undefined — that is the target switch.

CC     ?= cc
CFLAGS ?= -std=c99 -Wall -Wextra -g -O1 -I.
LDLIBS := -lm

SRC := $(wildcard *.c) $(wildcard cas/*.c) $(wildcard imath/*.c) $(wildcard pc/*.c)
OBJ := $(SRC:.c=.o)
BIN := ../../build/symcore-pc

$(BIN): $(OBJ)
	@mkdir -p ../../build
	$(CC) $(CFLAGS) -o $@ $(OBJ) $(LDLIBS)

%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@

test: $(BIN)
	$(BIN)

clean:
	rm -f $(OBJ) $(BIN)

.PHONY: test clean
```

- [ ] **Step 2: Build it**

```bash
cd <repo>/src/symcore
make -f makefile.pc 2>&1 | tail -30
```

Expected: `build/symcore-pc` produced.

Two failures are likely and both are ordinary porting work, not design problems:

- **Duplicate `main`** — `pc/main.c` and `pc/tests.c` may both define one. Compile only the entry point you want; drop the other from `SRC` with `SRC := $(filter-out pc/main.c,$(SRC))`.
- **Missing CE headers** (`tice.h`, `fileioc.h`) — means a file that should be `__TICE__`-guarded is not. Guard it, and note the file; upstream assumed those files were only ever built for the calculator.

- [ ] **Step 3: Verify the binary runs**

```bash

./build/symcore-pc 2>&1 | head -20
```

Expected: usage text or test output, not a crash.

- [ ] **Step 4: Commit**

